# 声称边界

这里约束语言。它不新增数据层。

## 观察不是解释

`observation` 记录这次看到了什么。`outcome_class` 才是解释。

进程在时限内没有结束，只是观察。它可以来自组件、runner、环境、网络或方法。VE-METHOD-001 的 R4 因此写成 `unclassified`，能力状态是 `insufficient`。R3 只表示“预期退出码没有出现”，并在方法里写明不再猜测原因。

## 没有观察到错误

fixture 全部 match，只能说：这些 fixture 在捕获到的环境、方法和 runner 版本下，输出与预期一致。

不能说：安全、可靠、无缺陷、可以投产、已经沙箱隔离、或这条能力在一切输入下成立。查看器在能力一节写明了这句话。

## 局部成功不能外推

下面这些跳跃当前都不允许：

| 观察到的 | 不能推出 |
| --- | --- |
| 一次协议握手成功 | 服务器可靠 |
| 一次文件读取符合预期 | 文件系统工具普遍正确 |
| 若干 fixture 都 match | 能力在未测输入上仍成立 |
| 这次没有报安全问题 | 对象是安全的 |
| 子进程环境被清洗 | 运行已被沙箱隔离 |
| 多个来源说法一致 | 结论为真 |
| 组件 A 与 B 各自 demonstrated | A 与 B 组合后仍成立 |
| 陈述被 demonstrated | 这个组件最适合用户 |
| 作者或项目声明支持某能力 | 该能力已被验证 |
| 观察与预期一致 | 已经知道原因，或已经作出符合性决定 |
| L0 被观察到且 L1 材料更全 | L2 可以讲得更宽 |
| admission=admitted | 认证、可投产或最佳选择 |
| 这次没有观察到错误 | 错误不存在 |

多个仪表若共享 runner、fixture、依赖或模型，不能把重复计数当成独立复现。三个模型的相同意见是一个相关来源。

`source_type` 已经能记下 `ve_test`、`independent_test`、`external_report` 和 `vendor_claim`。一致只是核对材料。准入仍要求至少一条 `ve_test`，并且自审记录在那之前就会停住。

## 能力多少不改变量规

方法事先写明的陈述就是量规。对象另外很强，不能补偿这条陈述失败。没有平均分，也没有用其他能力抵消。

对象超出当前方法时，正确说法是没有适用方法，或落在 envelope 外。这不是质量判断。现在还没有第二个方法，所以不为这个情况增加状态值。

## 方法与 runner 自己也要留版本

方法改含义就必须改版本，并写明影响哪些旧结果要重测。当前 VE-METHOD-001 还没有修订史。第一次修订之前不建空的变更文件。

参考 runner 的 v0.1 一致性测试就是方法目录中的 fixture 加上测试里的期望观察。见 [measurement_audit.md](measurement_audit.md)。

## 外部反例以后怎么进来

还没有提交系统。已有的结果类别已经能放下以后的分类：确认、未能复现、超出边界、组件失败、runner 缺陷、方法缺陷、环境失败、评估缺陷、无法归类。路径仍是：报告变成证据，再复现，再分类。不能因为是用户说的就采纳，也不能因为与旧结论冲突就丢掉。

## 自我测量，现在不计数

下面五件事值得在出现公开结论之后记录。现在没有公开结论，写 0 会假装已经测量过自己。所以仓库里不放计数文件。

1. 证据可追溯完整度：公开结论里，有多少能打开原始文件且哈希一致。
2. 复现一致度：评估者 A 和 B 按同一方法得到的观察是否一致。现在没有 B。
3. 更正延迟：有效反例进入记录之后，公开状态多久被改写。现在没有这种反例。
4. 过期证据比例：组件或方法已经变化，但仍被当成当前结论的比例。现在没有第二版本。
5. 评估缺陷数：VeriEnvelope 确认自己判错的次数。这个数字高不自动等于项目坏；藏起来才违反宪法。

不建仪表盘。校正延迟和复现一致度在有真实第二人、真实反例之前没有消费者。
