# ADR-002 方法、参考实现、验证结论是三层

## Context

如果判断规则只写在 Python 里，第三方就无法在不信任本仓库代码的情况下复现实验。如果第三方一跑出结果就写入官方结论，官方记录会失去边界。

## Decision

- 方法规格放在 `methods/`。规则编号对应的观察、结果类别和能力状态写在方法文件里。
- 参考 runner 只选择命中哪一条规则，再读取方法文件中的类别。它不私自把某条规则改成通过。
- `result.json` 是某一次测量的结论，并写明方法版本和 runner 版本。
- 第三方以后可以自建执行器或提交证据。提交不会自动成为 VeriEnvelope 的验证结论。
- 准入目前只可能建立在 `source_type=ve_test` 上。`independent_test` 和 `external_report` 可被保存，但不能单独开门。

## Reason

两名评估者要对照的是方法，不是某一份脚本的隐式习惯。这是 P3 的前提。

## Trade-offs

规则的“何时命中”仍然是 Python 条件，不是方法文件里的可执行表达式。这里故意不建规则引擎。行为由 fixture 测试锁住；方法文件中的 `when` 是给人读的条件。两边仍可能在文字上漂移，测试负责抓住行为漂移。

## Status

Accepted
