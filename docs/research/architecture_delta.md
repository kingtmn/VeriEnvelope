# 架构差分

对照物是 `docs/research/prior_work_audit.md` 里实际读过的文件，加上这一轮要判断的问题。曾经讨论过，不等于现在必须拥有。

## A. 已经完整存在

- 证据先于结论，未知保持未知，边界属于结论，错误不删除，现实可以否决，热度不能购买结论，方法自己可被审计。
- 一次结果绑定组件版本、方法版本、runner 版本、环境、fixture、run id。
- observation 和 outcome class 分开。超时不做因果猜测。
- 没有总分。`admitted` 不是认证。`candidate` 只是登记。
- 自审记录不能准入。第三方结果不能自动变成官方结论。
- 旧版本不继承准入。未识别的变化也要重测。
- fixture 失败、非零退出、超时和路径拒绝都会留下原始输出。

## B. 部分存在，这一轮补上或写明

- “0 错误不等于没有错误”原先只隐含在宪法里。现已写进宪法第 2 条、查看器和 `methodology/epistemic_limits.md`。
- 证据“可定位”原先没有检查文件还在不在。现已对关键文件做 SHA-256，准入前核对。
- 测量对象原先散落在结果字段里，没有被叫成一个词。术语表现在说明它是这些字段的合取，不新开 schema。
- 方法与 runner 的一致性原先靠测试，但没写成 v0.1 的符合性定义。现写在 `methodology/measurement_audit.md`。
- 历史不能按条关闭缺陷。限制写明了，实现继续推迟，见 ADR-007。

## C. 先前没有、但现在仍不加入代码的缺口

- 第二个仪器，以及仪器之间是否共享依赖。
- 外部反例的提交和复现流程。类别枚举已经放得下，系统没有。
- 组件新版本出现后，把旧证据标成“不再是当前证据”的登记状态。
- 容器隔离。只有 ADR-008。
- 评估者 B。P3 还没发生。

这些是缺口。它们不是因为旧项目提过就立刻实现。

## D. 旧思想在这里没有必要

- ADRA 的 Agent 任务窗口、攻击扰动分类和十五条款全文。
- d_an 的 ParentStrategy、学习循环和主张编号。
- 白盒学习的审批层级和“必须看见内部过程”这一定义。
- E0 的故障定位器和电池 toy。
- 蜂群几何错误边界。
- OPC 和多维路由框架。

它们解决的不是“一句组件陈述在给定绑定下是否成立”。

## E. 现在加入会造成过度设计

- 测量对象单独 schema。当前结果字段已经强制写出版本、方法、仪器、环境、fixture 和陈述。再包一层不会让缺字段变得更可见。
- 不确定度的数字区间。软件行为里的不确定主要是未测输入、非确定输出、网络和解释差异。Envelope 的未测区域和 Assurance 的复现说明已经能写这些话。没有第二组重复运行时，±σ 是装饰。
- 变更依赖图。重新验证触发名单已经说明哪些变化使旧准入失效。图要等真实版本差出现，才知道边怎么连。
- `stale` 状态。没有第二个组件版本时，这个值没有记录。
- 三检审批流。Pilot 没有第二个人，建审批只会让同一个人走三个章。
- 缺陷图、规则引擎、路由器、组合验证器、自我指标计数器。

## F. 等真实 Pilot 再加入

- Defect ID，触发条件见 ADR-007。
- 第二个 runner 的对照 fixture。
- 容器实现，见 ADR-008。第一个外部 MCP 的测量对象、方法和预期观察。
- 评估者 B 的一致度。
- 用户报告进入“复现或未能复现”的流程。
- 若某个真实对象没有适用方法，再决定要不要一个明确的“无适用方法”状态。现在用拒绝执行和 `insufficient` 不会把它说成失败。

## 六块模型

Identity、Capability、Assurance、Envelope、Evidence、History 仍然成立。攻击结果如下。

1. 测量对象没有装不进这六块。它是 Identity、Capability 和结果上的方法、仪器、环境、fixture 绑在一起。那是测试上下文，不是第七块数据。
2. Assurance 与 Envelope 都提到环境和权限，但问题不同。Assurance 回答这次运行凭什么值得看。Envelope 回答陈述在哪里停止。合并会把“怎么跑的”和“哪里不算”写成一段。
3. Evidence 是一次运行的文件。History 是对这些运行的后续判断，并用 `evidence_refs` 指回文件。混淆只会发生在把清单当成结论的时候。查看器把它们分成两节。
4. Envelope 有变成垃圾桶的风险。允许的内容只限于：测过的条件、已知限制、已知失败、未测区域、环境约束、版本约束、重测触发。不确定度写进未测区域或已知限制，不单开字段。
5. Method 和 Instrument 留在结果的上下文里。它们不是能力，也不是证据正文。
6. 可以想象的第七维是“这些仪表是否彼此独立”。现在只有一个 runner。没有第二份记录时，这个维度没有信息。不加入。

没有为了保住六块而把新问题塞进错误的字段。也没有因为想得出第七块就加字段。

## L0 / L1 / L2

它们和六块重复，如果被当成等级。作为问题则不重复：L0 是 Capability 那一问，L1 是 Assurance，L2 是 Envelope。

数据模型不使用这三个名字。查看器用八个问题，不用 L 标号，避免被读成铜银金。文档允许以后删掉这个记法。见术语表。

## 这一轮对二十二个问题的决定

| 问题 | 决定 | 原因 |
| --- | --- | --- |
| 测量对象必须先写清 | adapt | 用现有字段的合取。不新 schema |
| 仪器与主体分开 | adapt | runner、method、observation、outcome 已经分开。不建仪器类层次 |
| 观察不等于解释 | adopt | 宪法和 R4 已按此执行，文案补上 |
| 0 错误不等于没有错误 | adopt | 补进宪法、查看器、认识论文档 |
| 能力强弱不补偿单条失败 | adopt | 本来就没有平均分。写成句子，不加字段 |
| 多仪表 | defer | `source_type` 够记下不同来源。独立性和相关失败等第二个仪器 |
| 测量不确定度 | defer | 未测区域已能写。不加数字不确定度 |
| 变更事件 | defer | 触发名单在。不建“哪条旧证据被污染”的图 |
| 验证债务 | defer | 没有第二版本。不增加 stale 状态 |
| 三检 | defer | 留作以后避免一人包办定义、执行、解释和发布。现在不设审批 |
| 注册不等于认可 | adopt | 术语表写明 candidate |
| 错误账本按条关闭 | defer | ADR-007 |
| 结构白盒 | reject 模块 | 追溯已经在架构里。不把白盒定义成必须读源码 |
| 组合不继承 | adopt 为句子 | 架构文档写明。不实现组合系统，不加空字段 |
| 标准件三分 | defer | 没有适用方法时不应判差。等真实对象超出方法再加状态 |
| 强闭环才适合第一批 | adapt | 已是 ADR-004 的理由。不把开环分级写成类型 |
| 工具路由 | reject | 符合性不是选择。不为将来的筛选预埋空字段 |
| 选择不是验证 | adopt | 写进架构和认识论文档 |
| 方法版本是被测对象 | defer 空历史 | 规则已写：改含义必须升版本。VE-METHOD-001 尚无修订 |
| runner 是被测对象 | adapt | fixture 测试就是 v0.1 符合性测试。不做第二实现 |
| 现实反馈回路 | defer 系统 | 结果类别放得下。不建提交入口 |
| 诚实用语 | adopt | 查看器和宪法已改。schema 没有 safe/certified 字段 |

没有一条是因为“以前讨论过”而加入的。
